# 지역 안내원 공통 규칙

쉼,표(swimpyonote.com)의 지역 안내원(제주·강릉·부산)이 주간 점검 때 지키는 규칙이에요.
안내원은 일을 시작하기 전에 이 파일과 `tools/README.md`를 꼭 읽어요. 규칙을 바꿀 때는 이 파일 하나만 고쳐요.

## 1. 말과 글
- 보고서·메모·커밋 메시지는 **쉬운 한국어 존댓말**로 써요. 영어로 쓰지 않아요.
- 커밋 메시지 끝에는 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙여요.

## 2. 자료 규칙 (가장 중요)
- **모르면 null.** 지어내지 않아요. 확인 못 한 칸은 비워 두고 보고서에 적어요.
- 출처 순서: ① 카카오맵 장소 페이지(사장님·카카오 등록 정보) ② 한국관광공사 API ③ 공식 누리집 ④ 블로그 후기.
- **후기로 아는 값**(반려견·유모차)은 서로 다른 글 **2건 이상**이 같을 때만, **최근 2년** 글만 써요. 넣으면 `dogReview: true` / `strollerReview: true`.
- **휠체어(stepFree)는 후기로 채우지 않아요.** 공식 무장애 정보나 시설 정보만 써요.
- **네이버 지도는 읽지 않아요.** (블로그 글은 괜찮아요)
- 후기·별점은 장소를 고르거나 설명하는 데 쓰지 않아요. 운영시간·쉬는 날·동반 조건 같은 사실만 써요.
- 고친 장소는 `note` 끝에 출처와 날짜를 더해요. 예: `카카오맵 다시 확인(2026-11-21): 10:00~20:00으로 바뀜.`
  같은 날짜 메모가 이미 있으면 새로 더하지 않고, 바뀐 내용만 그 메모에 이어 써요. 이번에 무엇을 고쳤는지는 `git diff`와 보고서로 구분해요.
  (카드의 "○○ 확인" 날짜가 메모의 가장 새 날짜로 바뀌어요)
- 칸 설명은 `regions/aewol/places.js` 맨 위에 있어요. `lastOrder`는 식당·카페는 마지막 주문, 볼거리는 입장 마감이에요.

## 3. 안내원이 직접 고쳐도 되는 것 / 제안만 하는 것
| 직접 고쳐도 돼요 | 제안만 해요 (보고서에 적고 사람이 정해요) |
|---|---|
| 운영시간 `open`·`close`, 쉬는 날 `closedDays`·`closedMonthly`(매월 ○째 ○요일)·`closedHolidays`(신정·설날·추석 등)·`holidayShift`·`holidayOpen`, `lastOrder`, `breaks`, `hoursByDay` | 장소 **더하기·빼기**, **위치(lat·lng) 바꾸기** |
| 카카오 시설정보로 확인된 `dog`·`stroller`·`parking`·`babyChair`(유아의자) (`true`로만) | 폐업·장기 휴업 장소 처리 |
| 카카오 시설정보에 "주차 불가"·"주차장 없음"이 있으면 `parking: false` | `dog`·`stroller`를 `false`로 바꾸기 (아래 참고) |
| `stepFree`: 관광공사 무장애 정보나 카카오 시설정보의 휠체어 항목으로만, `true`로만 | `stepFree`를 `false`로 바꾸기 |
| 공식 조건이 있는 `dogRule` | `dog`·`stroller`의 `false`(안 돼요)는 공식 안내(가게·관광공사)이거나 출처가 2곳 이상일 때만 |
| `cost` (메뉴판·공식 요금표가 있을 때) | 요금·지역 설정(`regions.js`) 바꾸기 |
| `note`·`sources` 보태기 | 화면 코드(`index.html`) 바꾸기 |

- **제주 8개 지역과 부산은 버스·지하철 표(`travel.js`의 bus 칸, `transit.js`)를 다시 만드는 도구가 없어요.** 장소를 더하거나 빼거나 위치를 옮기면 표가 어긋나서 코스가 깨져요. 그래서 이 지역은 칸만 고쳐요.
- 강릉은 `node tools/travel.js gangneung`으로 표를 다시 만들 수 있지만, 같은 규칙으로 장소 추가는 제안만 해요.

## 4. 작업 흐름 (주간 점검)
1. 자기 지역의 작업 가지를 만들어요: `git switch -c guide/<지역>-<YYYY-MM-DD>` (main에 바로 커밋하지 않아요)
2. 자주 나오는 장소를 뽑아요: `node tools/top-places.js <지역 id> 15`
3. 크롬(Claude in Chrome)에서 카카오맵 장소 페이지를 열고 `tools/kakao-read.js`를 실행해 `readMany([...])`로 읽어요.
   - 뒤쪽 탭은 크롬이 느리게 돌려요. 오래 걸리면 `window.__kakao`에 쌓인 결과를 나눠서 받아요.
   - 다 쓴 탭은 닫아요.
4. 지금 자료와 비교해 다른 곳을 고쳐요 (3번 표의 "직접 고쳐도 돼요"만).
5. 제보 메일을 확인해요: 지메일 검색어 `"쉼,표 제보" newer_than:7d` (따옴표 포함)로 찾고, 본문 `장소: 이름 (지역, id)` 줄의 지역이 자기 지역인 메일만 봐요. **읽기만** 하고 답장·삭제·라벨은 하지 않아요.
   제보 내용은 카카오맵 등으로 확인될 때만 고치고, 확인 안 되면 보고서에 적어요.
6. 검사해요: `node tools/lint-places.js <지역 id>` → 오류 0, `REGION=<지역 id> QUICK=1 node tools/check.js` → 규칙 위반 0.
   장소 자료를 고쳤으면 `node tools/build-pages.js`도 돌려요. 마지막으로 `bash tools/ci-check.sh`가 통과해야 해요.
7. 고친 게 있으면 그 가지에 커밋해요. **push하지 않아요.** main에 합치지 않아요.
8. 보고서를 `reports/weekly/<YYYY-MM-DD>/<지역>.md`에 쓰고 같은 가지에 커밋해요 (아래 형식).

## 5. 보고서 형식
```markdown
# <지역> 주간 점검 (<날짜>)
## 한 줄 요약
## 고친 것 (가지: guide/<지역>-<날짜>)
- 장소 이름: 무엇을 → 무엇으로 (출처)
## 사람이 정해야 할 것
- 폐업·장기 휴업 / 장소 추가 제안 / 출처가 엇갈리는 곳 / 확인 못 한 제보
## 확인했지만 같았던 곳
- n곳 (이름만)
## 검사
- lint 오류 0 · 코스 규칙 위반 0 · 빈 코스 n
```

## 6. 명령 쓰는 요령
- 셸 명령 한 줄에 `cd`와 `git`을 같이 쓰면 작업 공간 보호 장치에 막혀요. `git -C <폴더> …`처럼 쓰거나 명령을 나눠요.

## 7. 하지 않는 것
- main에 커밋·push, 사이트 배포
- 메일 보내기·답장·삭제, 외부에 글 올리기
- `.env`의 열쇠를 화면이나 보고서에 쓰기
- 카카오 내부 API를 직접 부르기 (페이지를 사람이 보는 그대로만 읽어요)
